# Module contracts (shared by all build agents)

Read `PLAN.md` for the product and `lib/types.ts` for all domain types. **Do not change `lib/types.ts`**. If you really need a change, write it under "Requested type changes" in your final report instead.

Stack: Next.js 16 (App Router, read `node_modules/next/dist/docs/` before using Next APIs: `cookies()` is async, `params` is a Promise, middleware is now `proxy.ts`), React 19, Tailwind v4, TypeScript strict, zod v4, jose, bcryptjs, openai, sonner, lucide-react, clsx + tailwind-merge. Path alias `@/*` = repo root.

Only edit files inside your own area. Each area has one owner.

---

## 1. Data layer: `lib/db/**`, `scripts/**`, `data/**` (owner: DATA agent)

`lib/db/index.ts` must export (all **async**, server-only):

```ts
getMatchmakerByUsername(username: string): Promise<Matchmaker | null>
getMatchmakerById(id: string): Promise<Matchmaker | null>
listClients(matchmakerId: string): Promise<Profile[]>          // isClient && assignedTo === matchmakerId
getProfile(id: string): Promise<Profile | null>                 // any profile (client or pool)
listPool(gender: Gender): Promise<Profile[]>                     // all non-client profiles of that gender
updateClientStatus(id: string, status: CustomerStatus): Promise<Profile>   // also bumps lastActivityAt
listNotes(customerId: string): Promise<Note[]>                    // newest first
addNote(note: Omit<Note, "id" | "createdAt">): Promise<Note>       // also bumps customer's lastActivityAt
deleteNote(customerId: string, noteId: string): Promise<void>
listMatchActions(customerId: string): Promise<MatchAction[]>      // newest first
addMatchAction(a: Omit<MatchAction, "id" | "sentAt">): Promise<MatchAction>
updateMatchOutcome(customerId: string, actionId: string, outcome: MatchOutcome): Promise<MatchAction>
resetDemoData(): Promise<void>
```

Storage: seed JSON in `data/seed/` (profiles.json, matchmakers.json, notes.json) is loaded into memory. Mutations are stored in a JSON state file: `.data/state.json` locally, `os.tmpdir()` when `process.env.VERCEL` is set. The module is written so a Postgres implementation could replace it behind the same functions.

Seed content: generated by `scripts/generate-profiles.ts` (seeded Faker plus Indian lookup lists, deterministic). ≥150 female and ≥150 male pool profiles; 20 clients (10 M / 10 F, mixed statuses) split across 2 matchmakers:
- `priya` / `demo123` (Priya Sharma)
- `arjun` / `demo123` (Arjun Mehta)

Some seed notes per client. `npm run seed` regenerates the data.

## 2. Matching engine: `lib/matching/**` (owner: ENGINE agent)

`lib/matching/engine.ts` exports:

```ts
runMatching(customer: Profile, pool: Profile[], opts?: { excludeIds?: string[]; limit?: number /* default 20 */ }): MatchRunResult
```

The engine is pure, synchronous, has no I/O and imports nothing from db or ai. `lib/matching/weights.ts` holds the gender-specific weight profiles as data. The engine has unit tests in `lib/matching/__tests__/*.test.ts` (vitest).

## 3. AI layer: `lib/ai/**` (owner: AI agent)

`lib/ai/index.ts` exports (server-only):

```ts
explainMatches(customer: Profile, matches: MatchResult[], notes: Note[]): Promise<AiMatchInsight[]>
generateIntroEmail(customer: Profile, match: MatchResult, opts: { tone: EmailTone; matchmakerName: string }): Promise<IntroEmail>
summarizeNotes(customer: Profile, notes: Note[]): Promise<NotesSummary>
```

It uses OpenAI when `OPENAI_API_KEY` is set (model from `OPENAI_MODEL`, default `gpt-4o-mini`). Without a key, or on any error or timeout, it falls back to deterministic output (`source: "fallback"`). It never sends email or phone numbers to the LLM. It caches results in memory by hash of the inputs.

## 4. Auth + API routes: `lib/auth/**`, `proxy.ts`, `app/api/**` (owner: BACKEND agent)

Session: HTTP-only cookie `mm_session`, a JWT signed with `jose` (HS256, secret `AUTH_SECRET` with dev default), payload `{ sub: matchmakerId, name, username }`, 7-day expiry.
`lib/auth/session.ts` exports `getSession(): Promise<{ id: string; name: string; username: string } | null>` and `requireSession()`, which throws or redirects.
`proxy.ts` redirects unauthenticated page requests to `/login` and returns 401 for unauthenticated `/api/*` calls (except `/api/auth/login`).

All routes return JSON. Errors are `{ error: string }` with the right status code. Every customer route checks that the customer is assigned to the logged-in matchmaker (otherwise 404).

| Method & path | Body | Response |
|---|---|---|
| POST `/api/auth/login` | `{ username, password }` | `{ user: { id, name, username } }` + sets cookie |
| POST `/api/auth/logout` | – | `{ ok: true }` |
| GET `/api/auth/me` | – | `{ user }` |
| GET `/api/customers` | – | `{ customers: Profile[] }` |
| GET `/api/customers/[id]` | – | `{ customer: Profile }` |
| PATCH `/api/customers/[id]` | `{ status }` | `{ customer }` |
| GET `/api/customers/[id]/notes` | – | `{ notes: Note[] }` |
| POST `/api/customers/[id]/notes` | `{ type, body }` | `{ note }` |
| DELETE `/api/customers/[id]/notes/[noteId]` | – | `{ ok: true }` |
| GET `/api/customers/[id]/matches` | query `?ai=1` to include AI insights | `MatchRunResult` (already-sent matches are excluded; with ai=1 the top 10 get `ai` and `finalScore`/`tier` are re-computed, then re-sorted) |
| GET `/api/customers/[id]/history` | – | `{ actions: MatchAction[] }` |
| PATCH `/api/customers/[id]/history/[actionId]` | `{ outcome }` | `{ action }` |
| POST `/api/customers/[id]/summary` | – | `NotesSummary` |
| POST `/api/matches/intro` | `{ customerId, matchId, tone }` | `IntroEmail` |
| POST `/api/matches/send` | `{ customerId, matchId, subject, body }` | `{ action: MatchAction, customer: Profile }` (mock send; logs the action; moves status to "Match Sent" if it is earlier in the pipeline) |
| POST `/api/demo/reset` | – | `{ ok: true }` |

## 5. UI: `app/(app)/**`, `app/login/**`, `app/page.tsx`, `app/layout.tsx`, `app/globals.css`, `components/**`, `lib/ui/**` (owner: UI agent)

The UI talks to the backend **only via the HTTP routes above** (client-side `fetch`), so it never imports `lib/db`, `lib/ai` or `lib/matching` directly. It may import types from `lib/types.ts`.
